# The iOS app

A native SwiftUI client against the same SIP stack and the same shared business logic as
the Android app. This file is how to build it; `../docs/ios-port.md` is what is done,
what is not, and why.

---

## What you need

| | |
|---|---|
| macOS | 13 or later (14+ recommended — see "macOS 12" below) |
| Xcode | 15 or later. **Not** the Command Line Tools |
| JDK | 21, for the Gradle build of the shared module |
| Autotools | `brew install autoconf automake libtool` — Opus generates its `configure` |
| Apple Developer account | Only to install on a device. Not needed to build or to run in the simulator |

Everything else — PJSIP, OpenSSL, Opus, libvpx — is compiled from `../third_party/`.
Nothing is downloaded.

---

## One command

```bash
./build.sh ios              # simulator build
./build.sh ios --ipa        # unsigned device IPA — for BrowserStack
./build.sh ios --ipa-signed # signed device IPA — needs IOS_TEAM_ID
```

The first run cross-compiles PJSIP and takes roughly 30–60 minutes. It keeps a
content hash of each vendored tree, so the second run is a few seconds and a bumped
dependency rebuilds only itself.

---

## Or step by step

```bash
# 1. PJSIP, OpenSSL, Opus and libvpx -> ios/Vendor/pjsip/
ios/scripts/build-pjsip-ios.sh              # both platforms
ios/scripts/build-pjsip-ios.sh --device     # just the device, if that is all you need

# 2. The shared Kotlin module -> ios/Frameworks/Shared.xcframework
ios/scripts/build-shared-framework.sh Release

# 3. The Xcode project (already committed; regenerate after adding a source file)
python3 ios/scripts/generate-xcodeproj.py

# 4. Open it
open ios/WhatsAppV2.xcodeproj
```

Steps 1 and 2 must happen before the first Xcode build. The project has a build phase
that checks for both and fails with the command to run; without it the first symptom is
several hundred `Undefined symbol: _pjsua_create` lines, which name neither the missing
library nor the script that produces it.

## Getting it onto a device

### Through Xcode (the normal way)

1. Open `ios/WhatsAppV2.xcodeproj`.
2. Select the **WhatsAppV2** target → **Signing & Capabilities**.
3. Tick **Automatically manage signing** and choose your team.
4. Change the bundle identifier if `com.coraltelecom.whatsappv2` is taken on your
   account — any reverse-DNS string you own will do.
5. Pick your iPhone as the destination and press Run.

The capabilities the app needs are already in `WhatsAppV2/WhatsAppV2.entitlements` and
`Info.plist`: **Push Notifications**, and the **Voice over IP**, **Audio** and **Remote
notifications** background modes. Xcode will offer to add the matching capabilities to
your App ID; let it.

### As an IPA

```bash
IOS_TEAM_ID=ABCDE12345 ./build.sh ios --ipa-signed
```

Writes `build/ios-ipa/WhatsAppV2-signed.ipa` and then prints exactly what it is — the
architecture, the platform, the signing identity, the provisioning profile and the
device count. Install it with Xcode's **Devices and Simulators** window, with Apple
Configurator, or through TestFlight.

### For BrowserStack

```bash
./build.sh ios --ipa
```

Writes `build/ios-ipa/WhatsAppV2-unsigned.ipa`. BrowserStack re-signs uploads with its
own certificate, so an unsigned build is what it wants — and it is the only kind this
repository can produce without somebody's credentials. It is a real arm64 device build,
not a simulator one; `ios/scripts/verify-ipa.sh` proves which, and refuses to call a
simulator build an IPA.

## Checking an IPA you did not build

```bash
ios/scripts/verify-ipa.sh path/to/App.ipa
```

Reports the architecture and **platform** (a simulator build is also arm64 on Apple
silicon and the only difference is a load command), the signature, the embedded
provisioning profile with its device count, and whether the `Info.plist` carries the
background modes and usage descriptions iOS terminates a VoIP app for lacking. Needs no
Xcode, so it runs on any Mac.

---

## macOS 12

Xcode 15 needs macOS 13 and Xcode 16 needs macOS 14, so a Monterey machine tops out at
**Xcode 14.2** with the iOS 16.2 SDK. That is enough to build, to run in the simulator
and to run on a device. It is **not** enough to submit to the App Store, which requires
a current SDK.

Two things in this project also assume a newer toolchain and would need adjusting:
`ENABLE_BITCODE=NO` is already set (bitcode was removed in Xcode 16 and is merely
ignored by 14), and Kotlin 2.4's Kotlin/Native wants Xcode 15 or later. The practical
answer is to build on a machine running macOS 14 or later.

## How much is shared with Android

The `:shared` Kotlin Multiplatform module, which both platforms compile:

* SIP URI and `host:port` parsing and validation
* the account model and `AccountValidator`
* the call state machine, hold semantics, hang-up reasons
* registration state, the retry backoff, the expiry refresh policy
* codec preferences and the adaptive video ladder
* `Outcome`, `Secret`, redaction, the clock

Swift reaches it through `SharedFacade` (`shared/src/commonMain/.../ios/SharedFacade.kt`),
which exists because Kotlin/Native's Objective-C export is lossy for `Duration`, for
generic sealed interfaces and for value classes. The facade is in `commonMain` rather
than `iosMain` on purpose: it is type-checked by the JVM target on every ordinary Gradle
build, and its 20 tests run on both platforms.

What is **not** shared, and could not be: the UI (SwiftUI against Compose), the SIP
binding (Objective-C++ over pjsua's C API against SWIG-generated Java over pjsua2), and
the platform integrations (CallKit/PushKit against Telecom/FCM).
